# stack.json — the machine-readable index of the Web 4 stack

`stack.json` is the one document, contract `web4/1`, in which an agent — or a
person who would rather read a table than a README — can read the whole Web 4 /
agentic-internet infrastructure map the Flashy / Gord estate builds: nine
layers, each phrased as the question it answers, and for each layer the
repositories that carry its specification, implementation, product or tooling,
with the status and the GitHub visibility of each as **measured**, not as
intended. It is the twin of the human hub, [AgenteLabs/web4](https://github.com/AgenteLabs/web4),
and is meant to be served at `https://<hub-domain>/.well-known/stack.json`.

## Quick start

```bash
node vendor-stack.mjs check stack.json   # validate + lint; exit 1 on any finding
node vendor-stack.mjs list               # layer -> repo -> status -> visibility
npm test                                 # the whole suite, no install needed
```

## What makes it different

- **One measured document.** `stack.json` is the whole product. Every status
  and every visibility in it was read from GitHub on the `generated` date, and
  a value nobody has measured is `null` rather than a guess — a planned
  repository has `url: null` and `visibility: null`, because there is nothing
  yet to point at or to measure.
- **Drift-guarded by tests.** The schema (`stack.schema.json`) is the published
  contract; the checker (`vendor-stack.mjs`) is the code; `test/stack.test.mjs`
  asserts they agree on every enum, pattern, key set and vector, so the file a
  stranger reads and the code that checks it cannot quietly become two
  different contracts. Repo names are unique, every layer has a question and a
  repo, and the committed copy in `vectors/` is byte-identical to the root.
- **Statuses are honest.** `status` is one of `planned | draft | exists |
  private-intended`. Nothing here is `live`, `stable` or `1.0`; those are claims
  a fetch would have to settle and this document does not make them.
- **Visibility is measured, not assumed.** `visibility` is what GitHub
  reported, and when it disagrees with intent the disagreement is recorded, not
  resolved: `bastion` is `private-intended` and `public`, with an `x-note`
  saying so, and the checker refuses that combination *without* the note.

## Layout

| Path | What it is |
|---|---|
| `stack.json` | The document. `web4/1`. Regenerated by re-measuring, never hand-edited for a status. |
| `stack.schema.json` | JSON Schema, draft 2020-12 — the published contract. |
| `vendor-stack.mjs` | Dependency-free checker: `validate()`, `lint()`, `list`; `node:` builtins only. |
| `vendor-aao-check.mjs` | The AAO charter checker `MESH.md` documents, byte-identical to the `aao` repository's copy. Re-vendor, never edit. |
| `flashyos.roles.json` | The AAO charter — the single source the mesh handshake and `directory.fragment.json` derive from. |
| `vectors/` | Valid and invalid documents; each invalid one exists to produce one named error code. |
| `test/stack.test.mjs` | `node --test`: the document validates, every vector behaves, schema and checker agree. |
| `test/charter-conformance.test.mjs` | The charter validates and conforms under the vendored aao checker; UNKNOWN, never a pass, when `../aao` is absent. |
| `test/mesh-references.test.mjs` | Every file, script and filename `MESH.md` points at exists in the tree. |
| `.github/` | CI (lint + test, no install), issue and PR templates. |
| `CLAUDE.md` | What an agent working here needs to know, and the estate house rules. |

## Extending the document

Any object may carry keys prefixed `x-`; every other key is closed and the
checker refuses it. Put a note, a measured-at timestamp or a default branch in
an `x-` key; do not add a field to the contract without a schema change, a
checker change, a vector for it, and a test that the two agree.
